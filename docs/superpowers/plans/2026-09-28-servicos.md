# Parte C (serviços) — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adicionar, editar e remover serviços na interface.

**Architecture:** Novo `internal/agent/services.go` com `GET /api/mirror`, `GET /api/service/override`, `POST /api/service`, `POST /api/service/remove`, sobre o `Config`/`State` que já existem; `validateService` passa a dar `FieldError`. A página ganha um formulário no painel do serviço.

**Tech Stack:** Go stdlib + yaml.v3 (já existe); HTML/JS sem dependências.

**Spec:** `docs/superpowers/specs/2026-09-28-servicos-design.md`

## Global Constraints

- Nome fixo depois de criado; `npm` reservado; `validName` como hoje.
- Bloqueados com o serviço fora de NORMAL: `dir`, `host`, `override_yaml`, `require_free_ip`.
- Override em `<overrides_dir>/<nome>.override.yml`, validado com `docker compose … config -q` antes de gravar a config.
- Token do Kuma por serviço é segredo: nunca no estado; vazio mantém.
- Sem dependências novas. Textos PT-PT, comentários em inglês.
- Validação: `go vet ./... && go test ./... && golangci-lint run ./...`; `make e2e` no fim.

## Review Focus

1. **Override com um nome de serviço errado** (não existe no compose): recusado com a mensagem do compose junto do campo, nada gravado. Teste na Task 1.
2. **Adicionar com a pasta do override por criar** (`overrides_dir` ainda não existe): a pasta é criada. Teste na Task 1.
3. **Falha a gravar a config depois de escrever o override**: o override novo não fica a meio (escreve-se só depois de validar e antes de gravar; se a gravação da config falhar, o ficheiro volta ao que era). Teste na Task 1.
4. **Formulário aberto durante o refresh de 5 s**: o que foi escrito não desaparece. Verificação na Task 2.
5. **Remover o serviço cujo painel está aberto**: o painel fecha sem erro na consola. Verificação na Task 2.
